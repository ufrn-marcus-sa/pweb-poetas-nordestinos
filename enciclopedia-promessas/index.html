Enciclopédia — busca ao digitar

A mesma enciclopédia da outra feature, com duas diferenças: aqui não existe botão, a busca dispara sozinha a cada tecla; e nada aqui usa async/await. Todo o encadeamento é feito com .then() e .catch().

Por que uma promessa e não a outra

A cada tecla o navegador dispara uma requisição. A API leva um tempo variável para responder, e as respostas podem chegar fora de ordem: você digita cordel, depois cord, e a resposta mais lenta pode ser a primeira a chegar.

A saída é numerar as requisições. Cada busca guarda o número da vez que saiu, e o .then só escreve na tela se o número dele ainda for o mais alto. Uma resposta atrasada chega, vê que já foi superada, e sai sem desenhar nada. É o catch da corrida.

async/await e then/catch lado a lado

As duas abordagens fazem a mesma coisa e têm o mesmo desempenho: o await não trava a página, ele devolve o controle enquanto a resposta não chega. A diferença é de leitura.

Com async/await

async function consultar() {
  try {
    const res = await fetch(url)
    const dados = await res.json()
    desenhar(dados)
  } catch (err) {
    mostrarErro(err)
  }
}

Com then/catch

function consultar() {
  fetch(url)
    .then(res => res.json())
    .then(dados => desenhar(dados))
    .catch(err => mostrarErro(err))
}

O catch do encadeamento vale para os dois then, do mesmo jeito que o try/catch vale para o bloco inteiro. Dá para tratar cada etapa separadamente passando um segundo callback ao then, mas na prática o catch no fim resolve quase sempre.

Qual trecho roda primeiro

A ordem de execução não é a ordem em que o código está escrito. Clique para comparar as duas abordagens medindo o tempo de cada etapa.

A linha 3 está no mesmo lugar nos dois exemplos: logo depois da chamada da requisição. O que muda é o que o interpretador faz antes de chegar nela.

No then, a chamada não bloqueia nada, então a linha 3 roda antes de a função de fora terminar: a ordem fica 1, 2, 3, 4. No await, a função devolve o controle justamente ali, e a linha 3 só roda quando a resposta chega: a ordem vira 1, 2, 4, 3.

Repare que a resposta chega por último nos dois casos, e que em nenhum dos dois a página trava. Isso é o ponto: as abordagens são equivalentes em desempenho e diferentes só na leitura.

Técnicas: Promise, then, catch, encadeamento, segundo parâmetro do then, descarte de requisição obsoleta — origem: Receita 8 (Promessas). A busca do topo da página não usa async/await; só o painel comparativo usa.
